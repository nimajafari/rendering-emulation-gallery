prefers-reduced-transparency

Detects whether the visitor has asked their system to minimize transparency and blur effects, so a page can swap them for solid backgrounds.

Checking…
Try it: open Chrome DevTools → More tools → Rendering → Emulate CSS media feature prefers-reduced-transparency, then switch between no-preference and reduce. The banner above updates live.
Design approach: treat translucency as an additive enhancement, not a required one. Ship a solid, fully opaque baseline first, then layer in blur/transparency only when the browser reports no preference — that way a missing or unsupported preference never leaves a low-contrast surface behind.

Frosted-glass panel

Both panels render translucent with a backdrop blur by default, letting the striped backdrop bleed through. Only the right panel switches to an opaque, blur-free background under prefers-reduced-transparency: reduce, fully hiding the stripes.

Browser support: Chrome/Edge 118+. Firefox 113+ ships it behind the layout.css.prefers-reduced-transparency.enabled flag (off by default). Safari does not implement this media feature at all yet — the WebKit tracking bug has been open since 2016 — even though macOS and iOS both expose a "Reduce Transparency" accessibility setting at the OS level; that setting just isn't queryable from CSS on Safari today. Further reading: Chrome blog, "CSS prefers-reduced-transparency".
